Two things worth knowing:

1. This runs as a single replica with a Recreate strategy, and that is not
   configurable. The replicator takes a Redis lease at startup and exits if
   another instance holds it, so a second replica cannot run and a rolling
   update would deadlock. Expect a brief gap during upgrades: the old pod stops
   before the new one starts.

2. Readiness reflects initial load progress on the async path. A large dataset
   can take a while to become ready on first install. If it never does, check
   the logs for "Could not acquire writer lock" - that means another instance
   is already writing this Redis.
